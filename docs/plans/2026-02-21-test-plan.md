# MediaScout Starter Kit — Full Application Test Plan

**Date:** 2026-02-21
**Framework:** Playwright (headless, connecting to running dev server)
**Strategy:** UI-driven E2E — all tests interact through the browser. Real server, real DB, real auth. No mocks.
**Server:** `http://localhost:3000`

---

## Test Structure

```
tests/
├── setup/
│   ├── global-setup.ts       # Create test user, verify server running
│   └── auth.setup.ts         # Authenticate and save storage state
├── auth/
│   ├── registration.spec.ts  # Sign-up flows
│   ├── login.spec.ts         # Sign-in flows
│   ├── password-reset.spec.ts # Forgot/reset password
│   └── session.spec.ts       # Session persistence, expiry
├── navigation/
│   ├── public-routes.spec.ts  # Landing page, auth pages
│   └── protected-routes.spec.ts # Dashboard, chat, profile guards
├── pages/
│   ├── landing.spec.ts       # Homepage content and setup checklist
│   ├── dashboard.spec.ts     # Dashboard layout and links
│   ├── chat.spec.ts          # AI chat interface
│   └── profile.spec.ts       # Profile management
├── api/
│   └── diagnostics.spec.ts   # Health check endpoint
├── ui/
│   ├── dark-mode.spec.ts     # Theme switching
│   ├── responsive.spec.ts    # Mobile/tablet/desktop
│   └── accessibility.spec.ts # WCAG compliance
└── error/
    └── error-handling.spec.ts # 404, error boundaries
```

**Test User:** A real test account created via the registration flow in `global-setup.ts`, reused across tests via saved auth state.

## Test Execution Order

Tests should run in this order due to dependencies:

1. **Setup** — Create test user account
2. **Auth** — Verify auth flows work (registration creates reusable session)
3. **Navigation** — Verify routing and guards
4. **Pages** — Test each page's functionality
5. **UI** — Visual and responsive checks
6. **Error** — Edge cases
